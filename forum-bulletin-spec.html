论坛要闻栏 · 设计方案 v1.0

2026-11-18位置：列表页标题之下、帖子流之上三板块：思政 / 热点 / 快报
一句话结论

做成「三格并置、整组翻页」的要闻栏，不做单幅大轮播。

三个板块常驻可见，每 5.5 秒整组交叉淡入换成下一条——不是三格各转各的。高度锁死在 155px（含标签行与两行标题），代价是首屏少 1.2 条帖子，换来 3 条要闻。

01先说位置与代价

你要的位置是「标题之下、帖子流之上」。这个位置在论坛里是最贵的——它是首屏唯一能放内容的地方。我把现在的首屏预算量了一遍：

首屏构成（1440×900 视口）高度
吸顶工具条48px
标题区（h1 + 计数 + 分类说明）约 88px
单条帖子行（元信息 + 标题 + 2 行摘要 + 脚注）约 163px
现状：一屏可见帖子4.2 条
加 155px 要闻栏后（含间距 199px）3.0 条

少 1.2 条。这个代价我不打算藏着——但我认为值得，理由是要闻栏本身是内容，不是装饰。首屏从「4 条帖子」变成「3 条要闻 + 3 条帖子」，信息量是升的，只是内容类型变多了。

但如果做到 200px 以上，就变成「论坛被一个 banner 挤走了」，那就错了。所以下面所有尺寸都是从这个 155px 上限倒推出来的。

明确不做的事
  • 不做 16:9 大图通栏。668px 宽的容器里 16:9 是 375px 高，一屏只剩 1 条帖子。
  • 不做「首屏遮挡式」弹窗或全屏引导。
  • 不做比帖子标题更抢眼的字号。要闻栏是「提要」，不是「主体」。

02三种形态，我推荐第三个

A. 单幅通栏轮播常见做法

一次只露一个板块，剩下两个藏在圆点后面。整块占 220–375px 高。

B. 跑马灯横滑最省空间

无限向左滚动，只占 60px 高。但内容永远不会停，读不完，且最像廉价公告屏。

C. 三格并置 · 整组翻页推荐

三个板块同一水平线常驻可见，每格内部随节拍一起换图。高度锁 155px。

对比项A 单幅轮播B 跑马灯C 三格并置
三板块是否同时可见否，要等是是
占用高度220–375px约 60px155px
读得完吗要盯着等它转永远读不完一眼扫完
和论坛气质的距离像视频网站首页像车站电子屏像报纸栏目条
移动端勉强可横滑，很自然

选 C 的核心理由：你提了三个板块，而轮播的本质是「一次只能看一个」。三个板块地位对等，凭什么让「思政」在圆点后面排队等 11 秒？并置才符合它们的关系。

05「滚动」到底怎么滚

这是最容易做错的地方。三个板块如果各自独立计时，屏幕上会同时有三种频率的动，眼睛一直在追。所以：三格共享一个节拍，整组一起换。

0ms

组的第 1 条可见（思政 #1 / 热点 #1 / 快报 #1）

0–5500

静止。人读标题大概需要 3–4 秒，留 5.5 秒是给「读不顺再读一遍」的余量

5500ms

整组三格同步 opacity 1→0，110ms

5610ms

内容替换为组 #2，opacity 0→1，110ms

5720ms

完成。下一轮计时重新开始。总动效 220ms

行为规格为什么
切换方式交叉淡入，不做横向位移位移是 App 语言（卡片流）；淡入是纸媒语言（翻页）。位移还会带着视线往左跑
节拍5.5 秒3 秒是刷广告的节奏，读不完成句中文标题
hover / focus整组暂停鼠标停在某条上就是「我要看这条」
标签页隐藏document.hidden 时暂停否则切回来会看到它跳了好几条
减少动效prefers-reduced-motion 时完全不自动只留手动切换。这条是 WCAG 硬要求，也照顾晕动症用户
暂停按钮左下指示条右侧，一个文字「暂停 / 继续」WCAG 2.2.2：超过 5 秒的自动移动内容必须可暂停，且不能只靠 hover
指示条3 条 2px 短横，当前 18px 紫、其余 12px 灰短横线比圆点更像报纸页码，也更容易看清「这是第几组」
组数等于每板块条数（3 条 → 3 组）三板块数量必须一致，否则末组会有一格空着
这些是「AI 味」的高发区，逐条禁止
  • 禁止图片 hover 放大 / 加遮罩 / 出现「查看详情」按钮——那是电商
  • 禁止在图上压大标题和半透明黑渐变——那是视频网站封面
  • 禁止圆角 > 4px、禁止 box-shadow、禁止任何发光与描边渐变
  • 禁止用彩色圆点 + 数字做指示器（「1/3」的胶囊）
  • 禁止入场时逐格延迟 80ms 的错峰动画——那是落地页

06视觉语言：沿用现有 token，只加三个点

上一轮改造已经定了规矩：颜色稀缺才有指向性。这个原则在这里继续用——三个板块的区分只靠一个 5px 圆点，不靠背景色、不靠边框、不靠标签底色。

底色
--background 直接透出，要闻栏不套卡片、不加白底。不套卡片是关键——一旦套了，它就从「报纸栏目」变成「广告位」
分隔
三格之间只有 12px 空隙，没有竖线。要闻栏与帖子流之间也不加横线，靠 20px 留白断开
板块名
11.5px，foreground/85 作主体色；前面 5px 圆点用语义色
三个点色
思政 primary（现成紫）／热点 oklch(0.55 0.13 45) 赭／快报 oklch(0.52 0.09 155) 墨绿。饱和度都压在 0.09–0.13，且全页只出现在这三个 5px 圆点里
期号 / 时间
10.5px 等宽，foreground/45，右对齐。跟右侧「本周热议」序号用同一套等宽数字
标题
13px / 1.5 / 限 2 行 / foreground。比帖子标题（15.5px）小一档，明确「次要」
动效
只有 opacity 与 color，120 / 220ms。ease，不用 spring

与标题区的一处联动调整

现在标题区是三层：h1「校园论坛」→ 计数「共 24 条」→ 分类说明「有人在问，也有人在答。」再加上要闻栏，上半屏会出现四个层级，很碎。建议：

  • 把分类说明缩短到一行以内，或者只在「全部」之外的分页显示（进「求助」才显示「问一句不丢人」）
  • 要闻栏和分类说明之间只留 24px，不要再加分割线
  • h1 与要闻栏之间保持 26–28px，让 h1 有「报头」的分量

07数据从哪来

第一版不建表。论坛刚改完，为三张图动 schema 不划算。用静态数据模块，跟 lib/campus/notices.ts 完全同一种做法——那个文件里已经有 3 条公告是这么写的。

// lib/campus/bulletins.ts
export type BulletinBoard = "思政" | "热点" | "快报";

export type Bulletin = {
  id: string;
  board: BulletinBoard;
  title: string;
  image?: string;        // 缺省则自动走无图版式，不留白框
  href: string;          // 站内 /forum/xxx 或外链
  publishedAt: string;   // "2026-11-18"
  source: string;        // "校党委宣传部" / "后勤处"
  issue?: string;        // "第 12 期"，思政与快报用
};

// 三板块各取最新 N 条，对齐成"组"，保证每组三格都不空
export function listBulletinGroups(size = 3): Bulletin[][]

关键约束：三个板块的条数必须相等。否则最后一组会空一格，而空格是「未完成感」的最大来源。用 size 参数在取数时就截齐。

九条种子文案

上一轮我说过「现在的种子内容像通知，不像人说的话」。同理，这三块内容如果写成「XX 活动圆满举行」，要闻栏立刻变成宣传栏。所以每条都带一个具体物：数字、时间、地点、期号。

08图片：这个方案唯一的真实风险

说句实话：这个方案的成败不取决于布局，取决于你手上有没有 9 张能用的图。用 stock 图或者 AI 生成的插画，整个首屏立刻回到「demo」——比不做更糟。

合格的图
  • 校内实拍：会场、走廊、食堂窗口、操场、宿舍楼下
  • 官方通稿图、校媒公众号推文的题图（需确认授权）
  • 手机拍的也行——轻微倾斜、光线不均反而有人味
不合格的图（出现一张就毁掉整体）
  • 通用商务 stock：握手、会议桌、城市剪影、地球仪
  • AI 生成图：多人面部变形、手指数量不对、文字是乱码
  • 扁平滑板插画、卡通 icon 拼贴、3D 渲染的小人
  • 带明显水印、带平台 logo 的网图

规格

2.4 : 1（约 12:5）。裁切时保主体在水平中线，左右可各裁 10%
尺寸

接口、数据库、schema、右侧栏、帖子行——一个都不动

轮播不引库。项目里没有 embla / swiper，为了三格淡入装一个 30KB 的引擎不值得。核心就是一个 setInterval + 一个 index 状态，外加三个暂停条件（hover、document.hidden、reduced-motion）。移动端横滑交给 CSS scroll-snap，零 JS。

加载与空态

  • 首屏只请求当前这一组的 3 张图，其余 loading="lazy"。容器固定 aspect-ratio，不会有 CLS 跳动
  • 图片加载中显示极浅底色（--muted），不加骨架屏动画——一块会呼吸的灰块比静灰更吵
  • 某个板块一条数据都没有：整个要闻栏不渲染，不要把两格挤成三格，也不要显示「暂无内容」

10分两步做

  • STEP 1 — 结构与静态（约 0.5 天） 数据模块 + 组件骨架 + 三格栅格 + 无图版式 + 移动端横滑。不做自动翻页，先只显示第一组。这一步做完就能看出高度是否合适、首屏是否被压得太狠。
  • STEP 2 — 节拍与打磨（约 0.5 天） 交叉淡入、暂停条件、指示条、reduced-motion、图片接入与压缩、九条文案定稿。

    • 建议 STEP 1 做完你先在本地看一眼再决定 STEP 2 要不要改节拍或砍高度。如果 STEP 1 看完觉得首屏太挤，最省事的调整是把图压到 2.8:1（76px 高），整块降到 142px，不用推翻结构。

    11需要你定的四件事
