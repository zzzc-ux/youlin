分层架构

L6
应用层

L5

NextAuth v5 会话 bcrypt-ts 口令散列 botid 机器人识别 接口限流 文件上传 proxy 路由守卫 所有 /api/chat、/api/forum、/api/files 入口统一过鉴权与速率限制；上传落 public/uploads 或 Vercel Blob。
L4

Orchestration

L3
校园业务引擎
Domain Engine
意图分类 8 类 工具策略 7 读 / 4 写 单一路径编排执行 Trace 步骤回传 失物匹配 论坛草稿生成 语义帖匹配 + 关键词兜底 隐私脱敏 engine.ts 是全项目唯一执行路径：分类 → 工具白名单 → 参数校验 → 写入前预览确认 → 执行 → 生成答复；读操作可直接执行，写操作必须二次确认。
L2
知识检索
RAG Pipeline
文档装载 文本切块 向量嵌入 向量库存储 相似度检索 PDF 解析 unpdf 检索 CLI 校园规章、办事指南、通知公告经 pipeline 入库，问答时先检索再生成，减少模型臆造。
L1

Data & Infra

流式返回

前端实时渲染 + Trace 步骤展示

设计要点：业务判定不交给模型 —— 模型只负责「理解说什么」和「组织怎么说」，写什么、能不能写 由工具策略与参数校验决定；每一次工具调用都以 Trace 步骤的形式展示给用户，处理过程透明可回溯。

04

已知技术债与下一步动作

按「阻塞上线 → 影响体验 → 长期演进」排序
P0

TypeScript 类型未收敛

AI SDK 依赖版本存在类型差异，Three.js 类型报错，导致 pnpm build 无法保证通过。

P0

生产构建与公网部署未验证

当前仅保证本机开发模式可跑通，PostgreSQL 路径与公网部署缺少端到端验证。

P1

报修工单为内存态

工单存在进程内存，重启即丢，也未对接学校真实报修系统，需落库并补状态机。

P1

站内消息无主动通知

依赖用户手动刷新，需补轮询或 SSE 推送，否则交接链路容易断。

P2

自动隐私识别不完整

证件号、验证码、学号等敏感信息识别有遗漏，公开发布前需人工复核兜底。

P2

静态样例数据需替换

校园通知、余额、开放时间等为代码内样本，真实上线需接入校方数据源。
