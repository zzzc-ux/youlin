UI / UX Proposal · Forum Redesign

把论坛从「产品落地页」
改回「一块黑板和一屋子人」

现在的论坛页看起来像一份精致的 Demo：渐变大标题、毛玻璃卡片、光晕、扫光按钮。它什么都好，就是不像有人在里面说话。这一版方案做减法，把信息密度和人的痕迹加回去。

01

诊断：AI 味从哪里来 不是审美问题，是「装饰」压过了「内容」。以下每一条都能在 forum-board.tsx 里找到对应代码。

判断一个界面像不像 AI 做的，有个很简单的测试：把界面上所有文字都换成乱码，它还能不能看？如果还是一样好看，说明视觉本身在抢戏——那它就是装饰品，不是工具。

七个具体病灶

现象现在的实现为什么读起来「假」
紫色渐变铺满全场 indigo-500 → violet → fuchsia 同时用在标题渐变文字、分类激活态、头像底色、按钮阴影 这是 2024 年所有 AI 生成页面的默认色。一个颜色承担了六种语义，结果什么都没强调。
六色分类标签 CATEGORY_STYLE 给六个分类各配一套 rose / sky / violet / emerald / indigo / amber 颜色数量超过人的识别上限。用户记住的是「一堆彩色药丸」，不是分类。
卡片套卡片 每条帖子 = SpotlightCard + 圆角 2xl + 悬浮光晕 + 入场模糊动画 论坛的核心动作是「扫读标题」。卡片把一屏能看 12 条压成了 3 条，还让每条都长得一样重。
营销口吻的头部 40px 渐变标题「活动、社团和互助，都发在这里」+ 圆形徽标「校园论坛」 这是落地页的第一屏，不是工具的入口。论坛不需要说服你来，它只需要让你看见里面在聊什么。
正文全文铺开 列表里直接渲染 whitespace-pre-wrap 的完整 body 没有摘要层级 = 没法扫读。一条长帖把整个列表撑开，后面的帖子全被推走。
装饰性动效 BlurText / GradientText / ShinyText / spring layout 切换 / 逐条 0.05s 延迟入场 每次进页面都要等动画演完才能读。工具类界面里，动画是税，不是礼物。
没有时间感 时间统一格式化成 11/18 10:00 人不会说「11/18 10:00」，人说「十分钟前」。少了这一层，帖子就没有「刚发生」的体温。

还有一处结构性问题

现在帖子详情是用 ?post=xxx 在列表里原地展开的。这带来三个连锁问题：列表滚动位置丢失、无法分享到具体楼层、浏览器返回行为不符合直觉。论坛这种「点进去看、看完退出来」的场景，需要真正独立的路由。

保留了不该保留的
视觉装饰、动效、渐变
砍掉了不该砍的
信息密度、时间感、讨论的余温
缺失的关键一环
「谁刚刚说了什么」——论坛的心跳
02

方向与参考坐标 不追求「好看」，追求「耐看」和「一眼能读完」。

一句话定位：像一份每天早上会被人翻开的校内小报，而不是一个要拉新的 App。

取谁的长处

参考对象取它的什么不取它的什么
V2EX单列信息流、12–13px 的克制字号、几乎零装饰的列表、靠留白和分割线分层过时的表格布局和纯链接感
Discourse完整的论坛范式：分类、楼层、楼中楼、最后回复人、未读状态功能面板过多带来的复杂度
豆瓣小组中文社区的人文气：口语化标题、聊天的语气、话题而非条目老旧的排版密度
Hacker News极致的层级克制——整页只有一个色相，全靠字重和缩进排序无视觉层次导致的疲劳
少数派 / 即刻中文正文的排版质感：行高 1.75、字距微调、阅读宽度控制在 68 字符品牌感过强的编辑风格

明确不做的事

  • 不做大图 banner。论坛首屏的价值是「看见七条正在发生的事」，不是「看见一张图」。
  • 不做深色科幻感。校园论坛的使用高峰是白天课间和晚上宿舍，暖白纸底最省眼睛。
  • 不做拟物和插画。所有视觉预算给排版和留白，插画一律不要。
03

六条设计原则

01

内容即装饰

页面上任何一个视觉元素，如果不能帮用户更快找到或读懂一条帖子，就删掉。留白、分割线、字号差，是唯一允许的装饰手段。

要：用 1px 分割线 + 16px 行距给帖子分块
不要：用圆角卡片 + 投影 + 悬浮光晕给帖子分块
02

一个主色，三个语义点

整页只有一个强调色（墨绿），只出现在「当前分类下划线、主按钮、链接」。分类不用颜色区分，用中性标签 + 左侧语义小圆点。颜色一旦稀缺，指向性才成立。

要：分类标签统一 #F2EFE8 底 + 深灰字
不要：六个分类六种饱和色
03

密度优先于呼吸感

一屏（900px 高）要能看到至少 7 条帖子。每条帖子三层信息：元信息 / 标题 / 摘要 + 脚注。把「空气」留给段间距，而不是卡片内边距。

要：单条帖子高度 96–120px
不要：单条 180px 的卡片，一屏只放 3 条
04

时间必须是人话

所有时间显示相对值：刚刚 / 12 分钟前 / 昨天 21:40 / 11 月 14 日。悬停给绝对时间。列表脚注显示的不是发帖时间，而是「最后一条回复是谁、多久之前」——这是论坛的心跳。

要：「3 条回复 · 林知夏 2 分钟前」
不要：「11/18 10:00 · 3 条评论」
05

动效只允许 120ms 的颜色变化

不许模糊入场、不许 spring 位移、不许逐条延迟。唯一保留的过渡是 hover 时文字变深、背景变浅。界面应该「已经在等你了」，而不是「正在为你表演」。

要：transition: color .12s ease-out
不要：initial={{filter:"blur(6px)", y:16}}
06

允许不完美

真实社区里，标题会有口语、有错别字、有不规范的标点；有的帖子没人回，有的问题已经解决。界面要能容纳这些状态，而不是把一切修整成样板间。

要：「还没有人回复，也许你能帮上忙。」
不要：「暂无数据」
04

视觉语言 全部以 CSS 变量的形式给出，实现时直接落到 .forum-root 作用域，不影响对话页现有主题。

色彩

底不用纯白，用带一点点暖黄的纸白（#FBFAF7）。纯白在长时间阅读时会发刺，暖白更像纸。文字不用纯黑，用 #1A1917，避免生硬。

纸底#FBFAF7
输入/浮层#FFFFFF
正文墨色#1A1917
次级文字#4F4B45
元信息#75706A
分割线#E6E1D8
强调色 墨绿#2E5D4E
语义 赭红#B4552D
变量值用量与边界
--paper#FBFAF7整页底。占比 ~90%
--surface#FFFFFF输入框、弹层、信息条。占比 ~5%
--ink#1A1917标题、正文主色
--ink-2#4F4B45摘要、评论正文。对比度 ≈ 8.9:1
--ink-3#75706A时间、作者、计数。对比度 ≈ 4.9:1（12px 仍达标）
--line#E6E1D81px 分割线，唯一的分层手段
--accent#2E5D4E只允许三处：当前分类下划线、主按钮、链接 hover。全页占比 < 4%
--warn#B4552D只用于「寻找中 / 未解决」5px 圆点
硬性约束：除以上色值外，不再引入任何新色。尤其是紫色的任何分支（indigo / violet / fuchsia）——这一版全部禁用。

字体层级

系统字体栈（PingFang SC / HarmonyOS Sans / 思源黑体），不加载 webfont。数字统一 font-variant-numeric: tabular-nums，让时间、计数、楼层号在纵向上对齐。

间距

4pt 基准：4 / 8 / 12 / 16 / 20 / 24 / 32 / 48。列表条目上下内边距 16px，条目之间靠 1px 线分隔，不额外加 margin。主栏与侧栏间距 0（用分割线），侧栏内边距 22px。

05

信息架构 两块屏：一屏看有谁在说话，一屏看这句话说完了没有。

路由调整

路由对应变更
/forum帖子列表保留，重做视觉；支持 ?c=求助 深链到分类
/forum/[id]帖子详情新增。替代原来的 ?post=
/forum/new发帖（可选）首版用弹层；若后续要支持富文本与图片，再升级为独立页
/forum?post=xxx旧链接服务端 301 到 /forum/[id]，不破坏已分享的链接

07

组件规格 九个组件覆盖全部页面，均不含装饰状态。

组件结构尺寸 / 状态备注
ForumTopBar 品牌名 · 分类导航 · 搜索 · 发帖按钮 高 48px，sticky；当前项 2px 下划线 accent 移动端折叠：品牌 + 搜索图标 + 发帖
CategoryTabs 横向滚动文字标签 + 计数 13px / 400 → 选中 500 + 下划线 不用 pill、不用背景色块
PostRow MetaLine / 标题 / 摘要 2 行 / Footer padding 16px 0；高 96–120px hover：标题变 accent，整行底色 #F7F4EE
MetaLine 分类标签 · 地点/时间 · 相对时间 12px，gap 8px，分隔符「·」 分隔符用字符而非边框

不用随机色、不用渐变色。同一人在列表、详情、评论里必须同色——这是「人」的感觉，比十二色的彩虹头像强得多。

列表页标题区文案

现在是一句 40px 的 slogan。改成一个页面标题 + 一行实时状态：

校园论坛
今天 14 条新帖 · 37 人在逛
有人在问，也有人在答。

最后一句是可选的一行「编辑手记」，每周换一次。它的作用不是解释功能，而是让页面看起来有人打理过。

分类说明文案

分类一句说明（显示在分类页顶部，12.5px 灰字）
活动要去的事都写在这里，写清时间地点，别人好安排。
讲座值得听的，和听完想吐槽的。
社团招新、排练、约饭，都可以发。
招领捡到东西放这里，丢东西也放这里。
求助问一句不丢人，答一句也不费事。
闲置校内面交，不邮寄，别转账。

种子内容建议

现在数据库里的种子是 5 条公告式文案（「整理共享单车和捡拾操场垃圾，预计一小时」），像通知，不像人说的话。建议替换为 15–20 条带具体细节的帖子，覆盖全部六个分类，每条至少有一个可验证的具体物：门牌号、时间段、价格、天气、某个人的名字。

「三教 402 讲台下面」 「20 块，不送」 「九点半散场」 「靠窗第一个位置」 「37 路」 「工单还在已受理」

细节是可信度的来源。没有细节的内容，读者会自动判定为「填充物」。

09

状态与边界 每个状态都必须被设计，且都必须说人话。

状态呈现文案
首屏加载3 条骨架行，只有 1px 线 + 两条灰条，无脉冲动画—
列表为空居中，一行灰字这一栏还空着，等第一个开口的人。
搜索无结果灰字 + 「看看全部」文字链接没找到「{query}」，换个说法试试。
加载失败灰字 + 「重新加载」文字链接没拉到帖子，可能是网的问题。刷新一下试试。
帖子不存在灰字 + 返回列表这条帖子不在了，或者链接不对。
未登录发帖弹层内提示，不跳页得先登录才能发帖。登录后写的内容不会丢。
敏感信息被隐藏行内轻提示，不弹 toast手机号已自动隐去，需要的话可以在回复里私聊。
自己的帖子操作区出现「编辑」「删除」，非自己的不出现删除需二次确认，说明「删除后不能恢复」
关于 toast：现在大量使用 toast.success/error。建议只在「动作已发生且页面未更新」时使用（如删除、标记已解决）；表单校验、搜索无结果这类情况，直接写在字段下方或列表位置，不要再浮一层。
10

反 AI 味清单 可以直接贴进 code review checklist。出现任意一条，打回。

禁止

  • bg-gradient-to-* 的任何使用（含文字渐变）
  • indigo / violet / fuchsia / purple 色系
  • backdrop-blur、.glass、半透明卡片
  • SpotlightCard、光晕 shadow-[0_0_...]
  • BlurText / GradientText / ShinyText
  • framer-motion 的 layout、AnimatePresence 入场
  • 圆角 ≥ 16px（rounded-2xl / 3xl）
  • 图标单独上色（text-violet-600 之类）
  • 装饰性 emoji
  • 六色分类标签
  • 列表内展开详情
  • 卡片悬浮阴影 + translateY 位移

要求

  • 全页色彩：1 强调色 + 3 语义点 + 中性灰阶
  • 分层只靠 1px 线与留白
  • 圆角 4 / 6 / 8 / 10
  • 过渡 120ms ease-out，只改颜色和背景
  • 图标 16px，颜色 currentColor
  • 所有时间相对显示
  • 列表摘要 2 行截断（-webkit-line-clamp: 2）
  • 详情独立路由 /forum/[id]
  • 数字 tabular-nums
  • 键盘可达 + 2px accent focus ring
11

响应式与无障碍

断点

宽度布局调整
≥ 1024px主栏 720 + 侧栏 236完整形态
768–1023px单栏 720 居中侧栏内容折叠到列表顶部，只保留「本周热议」横向 3 条
< 768px单栏全宽，padding 16分类 tab 横向滚动；工具条 48px 只留品牌 + 搜索 + 发帖；发帖弹层全屏
< 400px同上摘要降到 1 行；脚注只保留「N 条回复」

无障碍

  • 所有正文对比度 ≥ 4.5:1；--ink-3（#75706A）在纸底上为 4.9:1，12px 灰字仍达标。
  • 分类 tab 使用 role="tablist" + 方向键切换；当前项 aria-selected。
  • 帖子标题为唯一 <a>，整行可点用 ::after 覆盖，不做 onClick 嵌套按钮。
  • 焦点样式统一 outline: 2px solid var(--accent); outline-offset: 2px，禁止 outline:none。
  • 评论列表用 <article> + <ol>，楼层号放 aria-label。
  • 相对时间用 <time datetime>，屏幕阅读器读绝对值。
  • 尊重 prefers-reduced-motion：虽然本方案几乎没有动效，仍需保留该查询。
  • 触控目标 ≥ 40px（移动端「回复」按钮加透明扩边）。

验收标准 设计走查时逐条对照，全部通过才算完成。

  • 页面内不存在任何 gradient、blur、backdrop-filter、彩色投影。
  • 全页只有 1 个强调色，且仅出现在分类下划线、主按钮、链接 hover 三处。
  • 1440×900 视口下，列表首屏可见 ≥ 7 条帖子。
  • 每条帖子高度在 96–120px 之间，摘要不超过 2 行。
  • 所有时间均为相对格式，悬停可见绝对时间。
  • 每个分类只有中性标签，语义状态只用一个 5px 圆点表达。
  • 点击帖子进入独立路由，返回后列表滚动位置保留。
  • 详情页正文行宽 ≤ 68 字符。
  • 同一用户在所有位置头像颜色一致。
  • Tab 键可遍历分类、帖子标题、回复框；焦点环可见。
  • 所有文字对比度 ≥ 4.5:1（用 DevTools 实测，不凭感觉）。
  • 375px 宽度下无横向滚动，发帖弹层为全屏。
  • 空态、错误态、无结果三种情况都有独立文案，且不出现「暂无数据」。
  • 刷新页面时没有入场动画，内容立即可读。
最后一条判断标准，适合贴在显示器上：如果你把这一页截图发给一个从没见过这个产品的人，他会觉得「这是一个有人在用的论坛」，还是「这是一张设计稿」？
